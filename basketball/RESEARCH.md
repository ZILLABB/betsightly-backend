# BetSightly NBA — research only

**Status: private offline prototype. No production deployment, API route, scheduled
job, website card, SportyBet call, betting slip or Telegram publication.**

The original basketball files in this directory are **legacy scaffolding**:
some training inputs and performance claims were synthetic or random. They must
not be used to claim predictive quality. The production FastAPI router keeps
basketball disabled. The maintained offline track is:

- `research_data.py`: licensed-source NBA game results/schedules ingestion
- `research_features.py`: deterministic pregame historical form features
- `research_model.py`: moneyline benchmark, chronological holdout, paper forecast
- `research_cli.py`: explicit local-only commands, without web server
- `tests/test_basketball_research.py`: schema and look-ahead regression tests

## 1. Get real NBA games using a free API key

Create a **free** key via https://www.balldontlie.io/ and set it **locally**
(never paste the key into source control).

The free NBA tier supports games, teams and players. It does **not** include
individual player game statistics, injuries, advanced NBA stats or betting odds.
The free API is limited to 5 requests per minute, so the downloader deliberately
waits at least 13 seconds between requests. A season may need dozens of pages.
Source: https://docs.balldontlie.io/

Linux / macOS:

```bash
export BALLDONTLIE_API_KEY="your-key"
python -m basketball.research_cli fetch --seasons 2022 2023 2024 2025
```

PowerShell (for the current terminal session only):

```powershell
$env:BALLDONTLIE_API_KEY = Read-Host "BALLDONTLIE API key"
python -m basketball.research_cli fetch --seasons 2022 2023 2024 2025
Remove-Item Env:BALLDONTLIE_API_KEY
```

Default dataset location: `data/basketball/research/nba_games.jsonl`.
`fetch` atomically replaces the snapshot only after all pages succeed.
Do not commit downloaded provider data. Multiple completed seasons are required.

## 2. Audit dataset and run the offline baseline

```bash
python -m basketball.research_cli report
python -m basketball.research_cli train
```

The training command requires **at least 300 eligible final games** (after
teams have five prior games in their respective seasons), plus enough distinct
calendar days for independent 70%/15%/15% chronological splits.

We train a regularized logistic-regression **NBA moneyline** baseline from
rolling points scored/allowed, wins, venue form and actual rest days. The model
chooses hyperparameters only on the validation period, then reports accuracy,
Brier score and log loss on a completely later test period, alongside a naive
constant-probability baseline. No randomized historical train/test split and
no pre-tipoff access to the current game's final score.

Model artifact: `data/basketball/research/nba_moneyline.joblib`.
Load only artifacts generated by your own trusted local environment; joblib
files are executable Python pickle containers.

**Important:** this early research benchmark cannot claim a betting advantage.
It has no licensed bookmaker historical odds, and therefore does not report
betting ROI, closing-line value, expected return or verified booking odds.

## 3. Generate paper-only forecasts

Include the scheduled season in the snapshot and explicitly choose the provider
fixture date; the input must include completed historical games and future
scheduled fixtures with enough historical form.

```bash
python -m basketball.research_cli fetch --seasons 2022 2023 2024 2025 2026
python -m basketball.research_cli paper --date 2026-10-25 \
  --output data/basketball/research/private-forecast.json
```

A forecast is allowed only after the model's training cutoff, for a genuinely
scheduled fixture present in the downloaded snapshot. If the provider returns
no eligible games or five historical same-season results per team are absent,
the private forecast list is empty. **We will not fill tiers with guesses.**

Results include probabilities and an explicit `not_for_betting` flag.
Booking code is always `null`. No publishing mechanism is imported.

## Safety and next gates

1. Confirm commercial re-use rights and retention requirements for data sources;
   a free access tier does not eliminate third-party data rights.
2. Expand source coverage with provider-approved player/injury/advanced data.
3. Add exact, timestamped historical bookmaker market lines before totals,
   spreads, value signals and any betting-profit backtest.
4. Run pre-registered, uninterrupted prospective paper tests with verified
   scoreboard settlements and calibration metrics.
5. Add isolated staging admin views only after offline data and model tests pass.
6. Do not mount public basketball routes or enable booking/distribution without
   a separate explicit release decision.

`python -m pytest tests/test_basketball_research.py -v` covers the offline
contract. Unit tests use synthetic fixtures **only as isolated test inputs**,
never as training data for real BetSightly predictions.
